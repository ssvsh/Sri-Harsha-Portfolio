PROJECT 04

StreamGuard

AI-Powered Real-Time Data Quality & Schema Evolution Platform

Project Overview

StreamGuard is a real-time data quality and schema evolution platform designed to protect event-driven systems from invalid data, breaking schema changes, and incompatible message contracts.

The platform validates Kafka events against versioned data contracts, evaluates schema compatibility, detects data quality issues, and maintains quality metrics across distributed event streams.

GenAI capabilities are integrated to analyze detected schema changes and generate migration recommendations, rollback strategies, and potential downstream impact assessments.

Technology Stack

Java 21 Spring Boot Spring WebFlux Apache Kafka MongoDB Redis Resilience4j GenAI / LLM React Prometheus Grafana Docker JUnit Testcontainers

Key Engineering Work

  • Designed a real-time validation pipeline for Kafka events using Java and Spring WebFlux.
  • Implemented versioned data contracts to validate incoming event structures against expected schemas.
  • Built deterministic schema compatibility checks to identify backward-compatible, forward-compatible, and breaking changes.
  • Added data quality validation for required fields, data types, value ranges, null constraints, and business rules.
  • Implemented schema version tracking and change detection using MongoDB.
  • Used Redis for frequently accessed schema metadata, validation rules, and runtime caching.
  • Implemented Kafka retry and dead-letter processing for invalid or repeatedly failing events.
  • Designed idempotent event-processing workflows to prevent duplicate validation and processing.
  • Integrated Resilience4j to provide timeout, retry, circuit-breaker, and controlled fallback behavior for dependent services.
  • Integrated an LLM gateway to generate migration recommendations and explain potential downstream impact of schema changes.
  • Exposed REST APIs for schema management, validation results, quality metrics, and compatibility analysis.
  • Built a React-based dashboard for viewing schema versions, validation failures, quality scores, and compatibility results.

Architecture

The platform follows a distributed, event-driven architecture:

React Dashboard → API Gateway → Contract Service → Validation Service → Kafka → Quality Processing → MongoDB / Redis

Schema changes are analyzed by the compatibility engine before the LLM layer generates migration recommendations and potential impact explanations.

Prometheus and Grafana provide system and application-level observability, including Kafka processing metrics, validation failures, processing latency, and service health.

AI Engineering Approach

StreamGuard intentionally separates deterministic validation logic from AI-based recommendations.

Core schema compatibility and data quality decisions are implemented using deterministic Java logic so that validation results remain predictable, testable, and safe for production workflows.

The LLM is used as an intelligence layer for explaining schema changes, identifying potential downstream risks, recommending migration approaches, and generating remediation guidance.

This approach prevents the LLM from becoming the source of truth for production validation decisions while still using GenAI where it provides meaningful engineering value.

Distributed Systems Concepts

  • Event-driven architecture using Apache Kafka.
  • Consumer groups and partition-based parallel processing.
  • Idempotent event processing.
  • Retry and dead-letter processing.
  • Distributed caching using Redis.
  • Schema versioning and compatibility management.
  • Reactive and asynchronous processing using Spring WebFlux.
  • Fault tolerance using Resilience4j.
  • Metrics and observability using Prometheus and Grafana.
